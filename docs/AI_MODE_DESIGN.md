## Когда включается

Режим хранится в `body[data-aimode]`, три значения:

| Значение | Подпись в UI | Поведение |
|---|---|---|
| `zero` | Если пусто | По умолчанию. Сначала точный поиск. Если 0 совпадений — вместо ошибки экран ИИ. |
| `always` | Всегда | Каждый запрос сразу идёт в ИИ, таблица точных совпадений не показывается. |
| `off` | Выключить | Только точный поиск; при 0 — обычный «ничего не найдено». |

Разовое включение — чип «ИИ-режим» в строке области поиска на главной
(`#aisw` внутри `.scope-line`): действует на один запрос и сам гаснет после поиска
(`runSearch()`). В режиме `always` чип подсвечен, клик по нему — выход из режима.

Постоянный выбор — те же три сегмента в двух местах, синхронно (`setAiMode()`):
поповер у чипа (`#ai-help-seg`) и быстрые настройки (`#qs-ai`, раздел «ИИ-поиск»).
Под сегментами — расшифровка выбранного режима (`AI_NOTE`, узлы `#qs-ai-note`,
`#ai-help-note`).

Поповер `.aihelp` — подсказка у чипа (абсолютная, не сдвигает страницу, хвостик к
кнопке, z-index на `.scope-line`): что делает режим, что даёт только ссылки на тексты
и слова и что ИИ ошибается.

В прототипе маршрутизацию делает `runSearch()`: короткий запрос → точная выдача,
фраза из 3+ слов при `zero` → экран ИИ (имитация «точный дал 0»).

## Экран ответа

Состояние живёт в `body[data-ai]`: `ready | load | empty | error` (`setAi()`).

- Шапка `.aihead`: сам запрос + серая строка «точных совпадений нет — предположения ИИ».
- `.aigrid`: слева строки сутт (`.aisec.cards`), справа колонка 210px с чипами слов
  (`.aisec.words`). Ниже 900px и в мобильной рамке — одна колонка, слова первыми.
- Строка сутты `.aicard`: номер (`.sid`, без индекса сегмента) + пали-название +
  перевод названия, ниже цитата `.qg` (пали + перевод). Волосяная линия и hover — те же,
  что у строк таблицы выдачи: экран должен читаться как та же выдача, а не другой сайт.
  Клик по строке — ридер на нужном сегменте (URL-паттерн `/dn22:2.2`).
- Много вхождений в одном тексте: видно только первое, остальные под кнопкой
  `.qtog` «ещё N совпадений в этом тексте» (`segMore()`, анимация высоты).
  Та же кнопка используется в раскрытой строке таблицы (`.cseg .cmore`).
- Чипы слов `.aiword`: пали + глосса; клик подставляет слово в поле и запускает обычный
  точный поиск (`aiWord()`).
- Подвал `.aifoot`: «На главную» + серое предупреждение, что ИИ может ошибаться.

### Состояния

- `load`: скелет повторяет геометрию ответа (та же сетка и заголовки, 3 строки
  `.aisk` и 5 чипов `.skp`) — при приходе ответа экран не дёргается. Статус
  «Ищем по смыслу · обычно 1–3 секунды». В прототипе через 1,8 с сам переходит в `ready`.
- `empty`: честный блок «Не нашлось ничего — ни точно, ни по смыслу», совет расширить
  область поиска и другие варианты (иначе/короче, палийский корень вместо перевода,
  описать другими словами).
- `error`: тихая деградация — серая строка «Подсказки по смыслу сейчас недоступны…
  Точный поиск работает как обычно» + «попробовать ещё раз», ниже «К точному поиску».

## Требования, которые нельзя потерять

- Любой язык запроса: длины текста не фиксировать, всё `text-wrap:pretty` / без `nowrap`.
- Светлая и тёмная темы, мобильный и десктопный вид — только токены `--dg-*`.
- Никакой уверенности в формулировках: это предположения, не точные совпадения.
- Путь назад к точному поиску всегда доступен (кнопка в состояниях `error`,
  чипы слов, «Искать точно как ввёл» в режиме `always`).
