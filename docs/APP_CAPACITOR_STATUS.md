# Приложение на Capacitor: что сделано и что осталось

Статус на 2026-09-11. Планы и модель сосуществования онлайн/офлайн — `docs/OFFLINE_PWA_PLAN.md`,
ручной чек-лист — `docs/APP_TEST_CHECKLIST.md`, шорткаты — `docs/PWA_SHORTCUTS.md`.
Исходники приложения — репозиторий `dg-app-full` (ветка `claude/ponytail-full-9vo71m`),
UI и офлайн-слой — `dg-node` (ветка `pwa`).

## Что сделано

### Архитектура

- **Тонкая оболочка.** `dg-app-full` больше не держит свою копию офлайн-слоя, core-bundle и
  сборщика базы: всё это строит `dg-node`, приложение копирует готовое
  (`build-page.js`, `build-assets.js`, `copyOfflineLayer`). UI, ядро поиска и офлайн-база —
  буквально те же файлы, что у сайта. Удалены `src/app.js`, `db-worker.js`, `offline-*.js`,
  `script-engine*.js`, `build-app-db.js`, `build-core-bundle.js`.
- **Шов платформы** (`public/offline/app.js` ↔ `dg-app-full/src/platform.js`): `distBase`,
  `onlineBase` (в приложении запросы «нужен интернет» уходят на dhamma.gift), `mapStatic`
  (TOC-снапшоты, Patimokkha-фрагменты), согласие на загрузку, драйвер хранилища.
- **Хранилище** — sqlite-wasm + OPFS в WebView (решение владельца): один и тот же слой для PWA,
  Android и будущего iOS; нативный SQLite для этого не нужен.

### Данные и офлайн

- Офлайн-библиотека собирается в dg-node (`npm run build-mobile-db`), публикуется как
  `siteroot/mobile-data/dg-mobile.db` + `db-manifest.json`.
- Прогресс загрузки: докачка по `Range`, повтор с чистым воркером при отказе хранилища
  (`createSyncAccessHandle`), знаменатель из манифеста, если сервер отдаёт chunked без
  `Content-Length`.
- Настройки: статус библиотеки, **размер**, «скачать/обновить/удалить», строка версии приложения.

### Нативное (то, чего веб не умеет)

- **Динамические шорткаты** (`DgShortcutsPlugin` → `ShortcutManager`), только реальные тексты,
  максимум 2; статические четыре в порядке владельца — Contents, Favorites & history,
  Dictionary, Memo (`res/xml/shortcuts.xml`, иконки из dg-twa).
- **Уведомление о загрузке** (`DgProgressPlugin`) + `DgDownloadService`: постоянное уведомление с
  процентами, foreground-service, `PARTIAL_WAKE_LOCK` и `WifiLock` — загрузка продолжается при
  выключенном экране.
- **Share** внутрь (ACTION_SEND → поиск на чистом тексте, чистит сайт) и наружу
  (`navigator.share`, если WebView его не даёт).
- **Deeplinks**: `autoVerify` на dhamma.gift/www/f./find., `configs/assetlinks.json` с обоими
  приложениями, роут `/.well-known/assetlinks.json` в `dg-fastify.js`.
- **Тема и сплеш**: DayNight, сплеш в цвете иконки, статус-бар следует за `data-bs-theme` страницы.
- **Навигация**: `target="_blank"`/`window.open` для своих путей — навигация внутри SPA (второе
  окно WebView не отдавало pushState-путь и не имело «назад»); внешние ссылки — в системный
  браузер; `native-bridge.js` вшит во все 42 собранные страницы (кнопка «назад» работала не везде).

### Режимы и ссылки

- Все ссылки на заучивание переведены на режимы ридера: `/<sutta>?mode=memorize`,
  `?mode=devanagari` (старые `/memorize/?q=`, `/d/?q=` убраны из dg-node).
- Локальные режимы (`bb`, `ai`, локальное зеркало TBW) показываются **только** по явному флагу
  `localStorage.forceLocal`; секретное включение — набрать в поиске `force_local` /
  `force_local_off`. Раньше «локальность» определялась по хосту, а у приложения хост
  `https://localhost` — поэтому их видели все.
- Запрос «нужен интернет» (деванагари, язык вне библиотеки) теперь не просто падает: приложение
  объясняет и предлагает открыть текст в браузере.

### Проверки и CI

- `test/app-ui/` в dg-node — 17 проверок без устройства: страницы против сайта, отсутствующие
  файлы, офлайн-поиск/ридер/TOC/настройки/memorizer, размер библиотеки, режимы, «нужен интернет»,
  состав динамических шорткатов, скрытость bb/ai. Запуск: `npm run test-app-ui`,
  `npm run test-app-progress`.
- `scripts/disk-guard.js` (+ cron каждые 10 минут): чистит только свои временные артефакты ниже
  6 ГБ, ALERT ниже 2 ГБ. Профили браузера удаляются после прогона.
- CI (`dg-app-full/.github/workflows/build-app.yml`): офлайн-слой из dg-node, сборка www в два
  этапа с TOC-снапшотом, проверки app-ui против поднятого dg-fastify, **APK и AAB**, база как
  артефакт; `DG_NODE_REF = pwa`.

## Что осталось

### 1. Проверка на устройстве (нужен телефон)

Уведомление и загрузка при выключенном экране; шорткаты в лончере (четыре статических + недавние);
шаринг внутрь/наружу; deeplink (`adb shell am start -a android.intent.action.VIEW -d
"https://dhamma.gift/dn22"`); сплеш, тема, статус-бар. Чек-лист — `docs/APP_TEST_CHECKLIST.md`.

### 2. Прод

- `.well-known/assetlinks.json` должен отдавать **Node** (роут есть, локально 200); в легаси-корне
  лежит файл только с TWA, из-за него верификация не проходит.
- Проверить отдачу `/mobile-data/dg-mobile.db`: `Accept-Ranges: bytes`, 206 на `Range`, без
  `Content-Encoding` (иначе ломается докачка и прогресс).
- Первая публикация AAB в Play: листинг, Data safety, versionCode.

### 3. Деванагари офлайн

`?mode=devanagari` конвертирует письмо на сервере; без сети приложение честно отправляет в
браузер. Чтобы работало офлайн, нужен локальный движок транслитерации (Aksharamukha/Pyodide,
~16 МБ, загружается по требованию) в офлайн-слое.

### 4. Полная база и дельта-патчи (решение: идём на патчи)

Сейчас офлайн-срез — ru+en (509 МБ). Полная база — 595 МБ, то есть **+86 МБ за 10 языков вместо 2**,
и вместе с этим уходят частные случаи: `langNeedsOnline`, отказы «языка нет в офлайн-библиотеке»,
расхождения паритета из-за отсутствующих языков.

Варианты обновления (по возрастанию работы):

1. **Полный файл + докачка** — как сейчас: 509/595 МБ на каждое обновление.
2. **Список изменений по `chunks`** — сервер публикует «изменилось N сутт», клиент всё равно качает
   файл целиком. Дёшево, трафик тот же.
3. **Дельта-патчи в один файл (выбран)** — сервер сравнивает `chunks` двух сборок (таблица уже
   есть, 36 204 хеша) и отдаёт патч: строки изменившихся групп `(sutta, kind, lang, translator)`.
   Клиент в одной транзакции делает `DELETE`+`INSERT` в `texts` **и в FTS-таблицу** (FTS5 это
   позволяет, полная пересборка индекса не нужна), обновляет `chunks` и `meta.build_id`, затем
   `quick_check`; при ошибке — откат и работа на старой сборке. Формат базы, поиск, навигация и
   паритет не меняются; прод-сервер не затрагивается. Оценка ~3 дня (генератор ~1, клиент ~1–1.5,
   тесты ~0.5–1). Поле `patches: []` в манифесте уже есть.
4. **Шардинг по книгам** — обновление трогает только изменившиеся книги, но поиск становится
   веерным по шардам (слияние `totalFiles`/`totalMatches`/`unique_words`/порядка) — это главный
   риск для паритета, плюс консистентность набора при частичном обновлении. 5–8 дней, брать
   только если понадобится уменьшить и первую загрузку.

Мелочь на потом: `VACUUM` после патчей делать нельзя (перезапись 595 МБ) — либо
`auto_vacuum=INCREMENTAL` и `PRAGMA incremental_vacuum` после применения, либо принять медленный
рост файла.

### 5. Локальный TTS (Piper) — варианты, без замера

Идея: офлайн-озвучка переводов (en/ru) нейронным голосом. Решение пока не принято, замер не делали.

- **A. WASM в WebView** (`onnxruntime-web` + piper-voice, готовые пакеты `@mintplex-labs/piper-tts-web`,
  `@pbji/piper-tts-web`): один код для APK и для PWA, нативного кода ноль. Минус: в WebView нет
  `crossOriginIsolated` → нет потоков (SharedArrayBuffer), синтез однопоточный; скорость на
  среднем телефоне под вопросом (это и должен был выяснить замер).
- **B. Нативно (Kotlin)** через sherpa-onnx (Apache-2.0, умеет VITS/Piper на Android): быстрее,
  играет в фоне через уже существующий foreground-service. Минус: нативный код и второй движок
  (WASM остаётся для PWA), если хочется офлайн и в браузере.
- **Голоса**: ~60–70 МБ на голос (en + ru ≈ 130 МБ), качать по требованию в OPFS/Cache, в APK не
  паковать; механика загрузки/прогресса/уведомлений уже есть.
- **Качество**: английские голоса заметно лучше встроенного Android TTS, русские — разборчивые, но
  грубее; Google-облако всё ещё живее, поэтому остаётся онлайн-опцией.
- **Пали**: палийского голоса нет; IAST читается правилами espeak-ng приблизительно (не хуже, чем
  сейчас). То есть офлайн-озвучка хорошо звучит для переводов, для пали — условно.
- **Лицензия — решается до публикации**: Piper — MIT, но его фонемизатор тянет espeak-ng под
  GPL-3.0 (`rhasspy/piper#93`). Варианты: отдельная `.so` с предложением исходников; модели с
  собственной фонемизацией (sherpa-onnx умеет часть без espeak); либо не включать в сборку.

### 6. Прочее

- **Паритет 20/22** (сейчас): решение владельца — либо тест в пределах языков библиотеки, либо FTS
  в `core/search-core.js` уважает `langs` (второе меняет онлайн-выдачу). С переходом на полную базу
  (п. 4) расхождение исчезает само.
- **Шрифты** subset Lato/Brahmi отсутствуют и на сайте (общий 404, не про приложение).
- **TOC-снапшот** можно убрать в саму базу (таблицей в `build-mobile-db.js`) — тогда копий данных
  не останется вовсе.
- **iOS** — не начато: JS-слой общий, нужны Swift-стороны плагинов (шорткаты, share, докачка),
  `npx cap add ios` поверх того же `www`.
