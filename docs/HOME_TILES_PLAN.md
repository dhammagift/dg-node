# Кнопки главной: перетаскивание, закрепление, свои ссылки, ярлыки PWA

Документ описывает, куда растут кнопки домашнего экрана. Часть уже сделана, часть — заложена
специально и ждёт решения. Ничего из «ждёт» сейчас не реализовано: это план, а не описание кода.

Смысл, ради которого всё затевается: dhamma.gift становится **порталом по Дхамме** — единой точкой
входа, из которой человек попадает и в сутты, и в словари, и в свои личные ресурсы. Кнопки главной
— это его собственный набор, а не наш.

---

## 1. Что уже работает

| Возможность | Где | Хранилище |
|---|---|---|
| Перетаскивание кнопок, порядок сохраняется | `search/js/home.js`, `wireTileDrag()` | `localStorage.dgTileOrder` = `{ "ru": [ключи], "en": [ключи] }` |
| Убрать кнопку с главной (крестик) | `renderTiles()` | `localStorage.dgTilesHidden` = `[ключи]` |
| Вернуть убранные | пункт «Вернуть убранные кнопки» в боковом меню | тот же ключ |
| Порядок вкладок в шторке = порядок кнопок | `openSheet()` | тот же `dgTileOrder` |

Порядок и состав намеренно живут в РАЗНЫХ ключах: убрать кнопку и переставить кнопки — разные
действия, и возврат убранного не должен сбивать расстановку.

Перетаскивание сделано на pointer-событиях, а не на HTML5 drag-and-drop: последний не работает в
мобильных браузерах. Мышью — после сдвига на 5 px, пальцем — после удержания 250 мс (иначе
отобрали бы прокрутку страницы).

## 2. Закрепить любую ссылку как кнопку

**Задача:** в шторке со ссылками у каждой строки появляется «закрепить» (та же звезда, что уже
помечает важные пункты, но в состоянии «нажата»). Закреплённая ссылка становится кнопкой на
главной, наравне со встроенными.

**Что для этого нужно поменять.** Сегодняшний `dgTileOrder` хранит только ключи встроенных плиток
из `menu-links.json`. Для закреплённых ссылок ключа недостаточно — нужны сами данные (подпись,
адрес, иконка). Поэтому формат меняется на список описаний:

```jsonc
// localStorage.dgTiles
{
  "ru": [
    { "type": "builtin", "key": "read" },              // плитка из menu-links.json
    { "type": "builtin", "key": "external" },
    { "type": "link",                                   // закреплённая ссылка из шторки
      "id": "pin:dpd",                                  // стабильный id (для повторного нажатия)
      "label": "Digital Pāḷi Dict",
      "icon": "dict",
      "tpl": "https://dict.dhamma.gift/?theme={{theme}}&q={{q}}",
      "blank": true },
    { "type": "custom",                                 // своя ссылка (см. §3)
      "id": "custom:1723800000",
      "label": "Мой словарь",
      "icon": "dict",
      "href": "https://..." }
  ]
}
```

Три типа вместо одного: `builtin` остаётся ссылкой на данные в `menu-links.json` (подпись меняется
вместе с языком и правками конфига), `link` и `custom` хранят данные у себя.

**Миграция.** При первом чтении: если `dgTiles` нет, а `dgTileOrder` есть — собрать `dgTiles` из
него (`{type:"builtin", key}`) и учесть `dgTilesHidden`. Старые ключи после этого можно не удалять
ещё пару релизов: чтение идёт только вперёд.

**Открытые вопросы (нужно решение владельца):**
- сколько кнопок разрешать максимум (сейчас на десктопе в строку помещается восемь);
- показывать ли закреплённую ссылку в шторке как «уже закреплена» (кажется, да);
- переносить ли набор кнопок между устройствами — это уже упирается в аккаунт (`/login`).

## 3. Свои кнопки

Пункт «Добавить свою» в конце сетки: подпись, адрес, иконка из готового набора (`ICONS` в
`home.js`). Поддержать в адресе те же подстановки, что и у ссылок меню (`{{q}}` — текущий запрос,
`{{theme}}` — тема): именно они превращают чужой сайт в «продолжение поиска», а не просто закладку.

Ограничение по безопасности: разрешать только схемы `http:`, `https:` и внутренние пути с `/`.
`javascript:` не пускать никогда — это чужой код в нашей странице.

## 4. Ярлыки PWA (`shortcuts`)

Установленное приложение показывает ярлыки по долгому нажатию на иконку (Android, Windows;
на iOS их нет). Сейчас `manifest.json` их не объявляет.

Ярлыки берутся из того же набора, что и кнопки главной — иначе получится второй, расходящийся
список. Ограничение платформы: **манифест статичен**, браузер читает его при установке. Значит:

- либо манифест отдаётся сервером динамически (`/manifest.webmanifest` собирается по сохранённому
  набору — но набор лежит в localStorage, до которого сервер не дотягивается, то есть нужен
  аккаунт или кука);
- либо ярлыки фиксированные, из четырёх самых частых действий (Читать Pāḷi, Поиск, История,
  Словарь), а «свои» ярлыки ждут аккаунта.

Разумный первый шаг — второй вариант: четыре статических ярлыка в манифесте. Динамические — после
того, как появится аккаунт, потому что без него набор просто негде хранить так, чтобы его увидел
сервер.

Заготовка:

```json
"shortcuts": [
  { "name": "Читать Pāḷi", "url": "/read.php", "icons": [{ "src": "/assets/img/dgsankhaonly.png", "sizes": "96x96" }] },
  { "name": "История",     "url": "/history.php" },
  { "name": "Словарь",     "url": "https://dict.dhamma.gift/" }
]
```

## 5. Порядок работ

1. Перевести хранилище на `dgTiles` с миграцией (§2) — без изменений в интерфейсе.
2. «Закрепить» в шторке ссылок.
3. «Добавить свою» кнопку.
4. Статические ярлыки PWA.
5. Синхронизация набора через аккаунт — вместе с остальным, что упирается в `/login`.

Шаг 1 стоит сделать раньше остальных: пока формат не поменялся, каждый новый вид кнопки пришлось
бы прикручивать к списку ключей сбоку.
