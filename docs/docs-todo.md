## Сделано (заход 9) — ракушка в навбаре ведёт обратно на боевой сайт

Владелец: «должен быть переход... а вот из документов обратно вернуться никак
нельзя» — логотип-ракушка в шапке доксайта вёл на `/docs/` (или `/ru/docs/`,
домашнюю страницу ЭТОГО билда), а не на настоящий корень сайта — выйти из доков
можно было только вручную стерев `/docs` в адресной строке.

Разобрался почему `href: '/'` в конфиге логотипа не помогает: компонент `Logo` из
`@docusaurus/theme-classic` сам прогоняет `logo.href` через `useBaseUrl()`, поэтому
`/` всегда становится `/docs/`. Обычный обходной путь в этом же файле —
`pathname://` (как у ссылки `/api-docs/` в сайдбаре) — для логотипа НЕ работает:
в исходниках Docusaurus (`Link.js`) baseUrl сознательно ДОБАВЛЯЕТСЯ ЗАНОВО после
снятия префикса `pathname://`, и это гасится только явным пропом
`autoAddBaseUrl: false`, а компонент `Logo` его не прокидывает — тупик именно для
логотипа (для обычных ссылок сайдбара/навбара трюк по-прежнему работает как раньше).
Более того, даже если бы просто переписать `href`-атрибут в DOM через JS постфактум
(как уже делает `langSwitch.js` для своих ссылок) — это тоже не сработало бы: клик
по логотипу обрабатывает React Router (это настоящий `<Link>`, не наш элемент), и
он использует свою внутреннюю цель навигации, а не то, что лежит в атрибуте `href`.
- ✅ Решение — перехват клика: `fixBrandLogoHref()` в `langSwitch.js` вешает
      слушатель `click` прямо на `.navbar__brand` (обычный, не capture — этого
      достаточно, т.к. у React обработчик висит на КОРНЕ, а не на самом элементе, и
      наш слушатель успевает сработать первым в фазе target), гасит событие
      (`preventDefault`+`stopPropagation`, чтобы React Router не успел
      перехватить) и делает настоящий переход `window.location.href = '/'` —
      корень БОЕВОГО сайта, тот же самый паттерн, что уже использует сама ракушка в
      приложении (`.dg-go-home`, `href="/"`, без привязки к конкретному домену —
      работает и на test, и на prod, и на других зеркалах).
- ✅ Вызывается из `onRouteDidUpdate()` (тот же хук, что и у остальных фиксов
      ссылок в этом файле), с защитой от повторного навешивания (`data-dg-home-fixed`)
      — DOM-узел логотипа переиспользуется React между переходами внутри SPA, слушатель
      вешается один раз и работает даже после клиентской навигации по сайдбару.
- ✅ Пересобраны оба билда, рестарт, проверено вживую: клик по ракушке с `/docs/sutta`
      (свежая загрузка) → уходит на настоящий боевой сайт (`/`, заголовок
      "Search Results - Dhamma.gift"); то же самое с `/ru/docs/sutta`; то же самое
      после перехода по сайдбару на другую страницу без перезагрузки (`/docs/rationale`
      → клик по ракушке → тоже уходит на боевой сайт, не залипает на `/docs/`).

## Сделано (заход 8) — реальный баг переключателя языка (не про слаги)

Владелец проверил живьём: `/docs/sutta/` → RU переключался верно, но
`/ru/docs/sutta` → EN был неверным, а `/ru/docs/principles` и `/docs/rationale`
переключали ВСЕГДА на sutta, независимо от текущей страницы. Разобрался: причина не
в слагах (те уже совпадали после захода 7), а в старом, ранее незамеченном баге
`langSwitch.js`: `onRouteDidUpdate()` обновлял `href` только у элементов с классом
`.dg-lang-link` — а сама ссылка при создании (`makeLangDropdown()`) получала класс
`dropdown__link` БЕЗ `.dg-lang-link`, то есть селектор никогда ничего не находил.
`ensureControls()` создаёт выпадающее меню языков только ОДИН РАЗ за сессию (есть
защита от пересоздания) — значит `href` обеих ссылок застывал ровно на той странице,
где меню было создано первый раз, и никогда не пересчитывался при переходах между
страницами внутри SPA (клик по сайдбару — это переход без полной перезагрузки).
Именно поэтому свежий URL в адресной строке (`/docs/sutta/`, полная перезагрузка)
работал верно, а переход по сайдбару на другую страницу — нет: линк переключения
языка так и указывал на ту страницу, с которой начиналась сессия браузера.
- ✅ Добавлен класс `.dg-lang-link` + `data-base` обеим ссылкам (En/Ru) в момент
      создания меню.
- ✅ `onRouteDidUpdate()` переписан: вместо одного общего `href = otherLangHref()`
      на все элементы — каждая ссылка пересчитывается по СВОЕЙ `data-base`
      (`hrefForLocale(el.dataset.base)`), иначе ссылка на «текущий язык» тоже
      получала бы адрес чужого языка.
- ✅ Пересобраны оба билда, рестарт, проверено вживую именно тем сценарием, что
      прислал владелец: `/ru/docs/sutta` (полная загрузка) → клик по сайдбару на
      «Принципы перевода» (SPA-переход, без перезагрузки) → линк EN верно стал
      `/docs/principles/` (было бы `/docs/sutta/` до фикса) → клик на «Обоснование» →
      линк верно `/docs/rationale/` → клик по нему → реально открывается EN Rationale,
      не Sutta.

## Сделано (заход 5)

- ✅ **Тема ещё раз перепрыгивала на светлую, теперь уже во время НАВИГАЦИИ (не только на
      первой загрузке)** — владелец поймал живьём на test.dhamma.gift. Причина глубже, чем в
      заходе 3: `@docusaurus/theme-common`'s `ColorModeProvider` слушает `storage`-события
      на общем ключе `theme` ВСЁ ВРЕМЯ, пока страница открыта (не только при загрузке), и
      любое значение не равное точно `"dark"` жёстко приводит к `"light"` (без учёта системной
      темы) — а любая встроенная на странице `<AppFrame>`-iframe (их почти на каждой user/*
      странице) при первой же загрузке для нового посетителя пишет в этот же общий ключ
      `"auto"` (сайт трёхзначный: light/dark/auto) — это НАСТОЯЩАЯ смена значения (null→auto),
      значит `storage`-событие в родительском окне доков реально прилетает. Хуже того — этот
      же код Docusaurus ЗАПИСЫВАЕТ свой неверный `"light"` ОБРАТНО в общий `localStorage.theme`
      (`persistColorModeChoice`) — то есть портится не только вид страницы доков, но и
      реальная настройка темы САЙТА, которую увидит и основное приложение при следующем
      визите. Проверено напрямую (synthetic `StorageEvent` с `newValue:'auto'` на уже тёмной
      странице) — оба эффекта воспроизвелись и оба устранены: `themeFix.js` теперь ещё и
      слушает `storage`, откладывает проверку на следующий тик (даёт коду Docusaurus сначала
      напортачить), затем восстанавливает и правильный `data-theme`, и ПЕРЕЗАПИСЫВАЕТ общий
      ключ обратно в исходное значение (`"auto"`), а не только красит текущую страницу.

      старую позицию скролла (`history.scrollRestoration`, дефолт `'auto'` — штатное поведение

      Проверено: клик → scrollY=3447 → F5 → снова 3447 без фикса. Новый `scrollFix.js`
      переключает `history.scrollRestoration` на `'manual'` и обнуляет скролл при чистой
      загрузке без хэша в адресе (якорные ссылки на конкретный заголовок продолжают работать).
- ✅ **Изображения на «Принципы перевода» и «Обоснование»** — тем же способом, что на главной
