# app-ui — проверки сборки приложения (Capacitor) без телефона

Приложение — это тот же билд сайта, поэтому все различия, которые доезжают до телефона, приходят
из сборки: страница, которую не скопировали (и Capacitor отдал вместо неё `index.html`), скрипт,
который приехал как HTML и умер `SyntaxError`, потерянный TOC-снапшот. В браузере с devtools это
не видно — видно здесь.

## Запуск

```bash
# один раз: playwright-core (в dg-app-full он не в зависимостях — тестовый инструмент)
cd dg-app-full && npm install --no-save playwright-core@1.49.1

cd ..            # корень dg-node
node test/app-ui/run-all.js                      # быстрые проверки
DG_APP_UI_ALLOW_DOWNLOAD=1 node test/app-ui/run-all.js   # + скачать базу, если её нет в профиле
```

Требуется собранный `dg-app-full/www` (`npm run build`) и запущенный сервер сайта для сравнения —
pm2-процесс `test` на `:3003` (переопределяется `DG_SITE_URL`).

## Что проверяется

| Файл | Что ловит |
|---|---|
| `check-pages.js` | каждая страница меню/плиток открывается как на сайте, а не как страница поиска (семейство «History/Materials/grammar открывали поиск») |
| `check-assets.js` | нет отсутствующих файлов и нет ошибок страницы, которых нет на сайте; плюс наличие TOC-снапшотов |
| `check-offline.js` | офлайн-стек: поиск, ридер по pushState-маршруту, `/api/toc`, настройки, строка версии, memorizer, наличие моста в легаси-страницах (кнопка «назад»), отсутствие ссылок на `read.php` |
| `check-progress.js` | **скачивает 509 МБ** и проверяет карточку прогресса на chunked-сервере (без `Content-Length`): проценты, «X из Y МБ», полоса заполняется, финал показывает реальный размер |

`check-progress.js` не входит в `run-all.js` — он качает всю базу. Запускать отдельно:

```bash
node test/app-ui/check-progress.js
```

## Диск (важно)

Проверки с базой создают браузерный профиль на ~500-900 МБ. Правила, чтобы это не повторило
инцидент (профили заполнили 49 ГБ диск до 100% — сервер мог упасть):

- профиль **удаляется по завершении** проверки (`DG_APP_UI_KEEP_PROFILE=1` — оставить);
- скачивание базы разрешено только с `DG_APP_UI_ALLOW_DOWNLOAD=1`, и только если свободно ≥ 3000 МБ;
- `scripts/disk-guard.js` (cron каждые 10 минут) следит за диском: ниже 6 ГБ — удаляет временные
  артефакты тестов (только свои профили и /tmp-кеши), ниже 2 ГБ — пишет ALERT и, если задан
  `DG_ALERT_WEBHOOK`, шлёт JSON в вебхук.

```bash
node scripts/disk-guard.js          # проверить/почистить сейчас
tail -20 test/.disk-guard.log       # что сторож делал
```

## Устройство

- `lib.js` — общее: поиск `dg-app-full` (`DG_APP_PATH`, иначе `./dg-app-full` или `../dg-app-full`),
  запуск серверов, браузер из `playwright-core`, профили в `test/.app-ui-profiles/`.
- `server-app.js` — то, что делает Capacitor: неизвестный путь отдаётся корневым `index.html`
  (поэтому отсутствующая страница выглядит как поиск). С `--strict` ассеты отдают 404 — так
  проверка отличает «не скопировали» от «отдали».
- `server-chunked.js` — база отдаётся **без** `Content-Length`, как на реальном деплое; на этом
  ловится прогресс без знаменателя.
- Профиль `library` общий для `check-progress.js` и `check-offline.js`: 509 МБ качаются один раз,
  дальше офлайн-проверки переиспользуют OPFS.
- Переменные: `DG_APP_PATH`, `DG_SITE_URL`, `DG_APP_PORT` (8099), `DG_CHUNKED_PORT` (8097),
  `DG_PLAYWRIGHT`, `DG_CHROMIUM`, `DG_PROFILE_ROOT`.

## Что этими проверками не покрыто

Устройство: уведомление в шторке и его проценты, foreground-service и wake lock (загрузка при
выключенном экране), кнопка «назад» как нативная, шорткаты в лончере (статические + динамические),
шаринг внутрь/наружу, сплеш и статус-бар. Ручной чек-лист — `docs/APP_TEST_CHECKLIST.md`.
