## Открыто

- [x] **Ctrl+K не работает.** Причина: в настоящем Chrome/Edge Ctrl+K — зарезервированный
      браузером шорткат (фокус адресной строки с `?` для поиска), keydown до JS страницы
      не долетает — не лечится со стороны страницы никак (та же история была с Ctrl+K в
      Firefox). Настоящий фикс: у `@easyops-cn/docusaurus-search-local` есть штатная опция
      `searchBarShortcutKeymap` — переставил на `/` (было `mod+k` по умолчанию). Теперь и
      сам биндинг, и ВИДИМЫЙ бейдж-подсказка в поле поиска показывают `/` вместо
      сбивающего с толку "Ctrl K". Заодно убрал свой отдельный костыль-clientModule
      `searchShortcut.js` — он дублировал то, что теперь настраивается штатно.
- [ ] **Дропдаун языка / Ctrl+K / все правки этой сессии — деплой на test.dhamma.gift.**
      Причина найдена (не предположение): `git status` показывает, что вся работа за эту
      и предыдущую сессию до сих пор НЕ закоммичена и не запушена в `origin`
      (github.com/dhammagift/dg-node) — test.dhamma.gift обслуживается отдельным деплоем и
      всё ещё крутит версию ДО начала этой работы. Проверено на примере жалобы "переключение
      языка кидает на главную вместо той же страницы" — локально (тот же билд) переход с
      `/docs/dhamma-principles` уже корректно ведёт на `/ru/docs/sutta/`, баг в
      `PAGE_PAIRS`/`langSwitch.js` не воспроизводится. Владелец сам решит, когда пушить —
      после пуша+деплоя нужна одна сверка живого test.dhamma.gift.
- [ ] **Admonitions по остальным страницам — ДОЗИРОВАНО, не по умолчанию.** Владелец
      прямо поправил: не заваливать admonitions/техданными весь текст, писать для

## Сделано (заход 3)

- ✅ **Тёмная тема сайта → светлая в доках, исправлено по-настоящему.** Причина
      (найдена в исходниках `@docusaurus/theme-classic/inlineScripts.js`, не
      предположение): у сайта тема трёхзначная (`light`/`dark`/`auto`), а
      встроенный no-flash скрипт Docusaurus понимает только `light`/`dark` —
      значение `auto` из общего `localStorage.theme` подставлялось в
      `data-theme` буквально, под такое значение нет CSS-правил → страница
      молча рендерилась светлой независимо от системной/сайтовой темы (сама
      явная `dark` уже работала верно, баг был именно в `auto`, это подтверждено
      воспроизведением до и после). Новый clientModule `themeFix.js`
      досчитывает `auto` в реальный `light`/`dark` по системной теме ДО
      гидратации React — только атрибут на `<html>` в самом докс-билде, общий
      ключ `theme` не трогается (иначе испортил бы собственную индикацию
      «авто» у сайта). Проверено playwright: сайт `theme=auto` → доки открывают
      тёмную тему и на десктопе, и на мобильном.
- ✅ **Принципы Дхаммы — клик по сутте скроллит к ридеру.** Список сутт длиннее
      экрана (особенно на мобильном) — читатель кликал и не видел, что вообще
      изменилось, потому что ридер был ниже экрана. `SuttaBrowser.jsx`: клик по
      пункту теперь ещё и `scrollIntoView({block:'center'})` на сам iframe.
- ✅ **Ссылки на конкретные строки сутт вместо целых текстов** — прошёл по

      нашёл точный сегмент для КАЖДОЙ из 13 цитат на странице «Принципы Дхаммы»
      (не осталось ни одной, которую не нашёл — ничего не подставлено

      404) и ещё провалит сборку как «битую» — `SiteLink` использует штатный

      `dict.dhamma.gift` — это ДРУГОЙ реальный сайт, не трогал, остался
      абсолютным. Пересобрано, `onBrokenLinks: 'throw'` проходит на обоих
