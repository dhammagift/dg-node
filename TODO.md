нюансы по п.5 (поиск, молниеносная загрузка):
- сделано в ветке `speed` (не main, не claude/todo-md-updates-l9xlnm) — см. коммит с этим текстом.
- сервер: `/search?...&fast=1` — только grep + skeletonDB, без единого чтения файлов сутт, отдаёт список сутт (id/category/title/mr) И полный wordReport сразу (word report строится прямо из сырых данных grep, независимо от цитат — как в легаси new/words.sh). сортировка на сервере — category, потом mr по убыванию.
- новый роут `/search/enrich?...&ids=...` — догружает цитаты/контекст только для запрошенных id, тоже через grep (`-B/-A` контекст), без JSON.parse целых файлов.
- обычный `/search` (без fast) не менялся по контракту — та же форма ответа, что и раньше, просто теперь это фоновая догрузка остального.
- клиент (res/index.html + search-render.js): fast=1 → рендер сразу с "Loading..." в колонке цитат → /search/enrich для видимой страницы → фон грузит остальное. заход через ?report=words вообще не запускает догрузку цитат, пока не переключишься на "Тексты".
- протестировано backend-only на реальном dn22 (root/variant/en-sujato/ru-o, реальные файлы из suttacentral/sc-data и dhammagift/offline-data) — curl'ом, полное совпадение /search/enrich с обычным /search. НЕ протестировано на полном корпусе и в браузере — в песочнице нет ни SC_BILARA/DG_OFFLINE, ни public/assets (симлинк на легаси, физически отсутствует). нужно прогнать на реальной машине по чеклику из плана (там же — сверить, что DG_OFFLINE в проде реально резолвится в рабочий путь с ru-переводами, судя по всему это может быть не /home/user/offline-data/dhammagift, а симлинк на /var/www/html/assets/texts).

нюансы по п.9/10 (autopali, словарь):
- скрипты (`autopali.js`, `paliLookup.js`) и так подключаются динамически через `settings.js` — НЕ через `<script src>` в HTML, трогать это не нужно.
- реальная причина, почему не работало локально на Windows: не хватало данных — `public/assets/texts/sutta_words.txt` и `public/assets/js/standalone-dpd/*` (offline DPD). Это вложенные symlink'и легаси-репо на офлайн-данные, которые не материализовались при `core.symlinks=false`. Скопированы вручную с диска из `C:\soft\dg\assets\...` для локального dev-паритета (в прод и так резолвятся через настоящий symlink). Аналогично скопирована `assets/svg/dpd-logo-dark.svg` (иконка в попапе словаря). `assets/svg/comment-slash.svg` отсутствует и в легаси-репо — не критично (иконка состояния "словарь выключен").

нюансы по п.11 (смена языка):
- реальный источник бага был НЕ в обработчике Ctrl+Shift+1 самом по себе, а в КОНФЛИКТЕ с отдельным, более старым обработчиком `Ctrl+1` (легаси-механизм `preferredLanguage`, settings.js) — он проверял только `ctrlKey && key === "1"`, без учёта Shift, поэтому срабатывал ОДНОВРЕМЕННО при нажатии Ctrl+Shift+1 и делал старый переход на `/ru/` → catch-all → `/?q=ru`. Добавлена проверка `!event.shiftKey`.
- Ctrl+Shift+1 и кнопки en/ru в настройках теперь используют `window.setSiteLanguage()` (dhamma-i18n.js, localStorage `dhammaLanguage`) — без навигации/перезагрузки. Backend-редирект для старых `/ru`-ссылок сознательно не делали (см. п.11 выше — решили не делать).
- правки в `settings.js` внесены в `public/overrides/js/settings.js` (копия, а не оригинал в `public/assets/js/`, который остаётся симлинком на легаси-репо и не коммитится).
